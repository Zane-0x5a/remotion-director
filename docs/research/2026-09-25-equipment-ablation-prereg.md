## 3. 假设与预测

### 3.1 假设

- **H1**：在当前模型上，F 相对 N 不再净正，即 N ≥ F。
- **H2**：工序和人格这一层保留了价值，即 M ≥ N。
- **H3**：F 会压缩媒介范围。在画面驱动的 brief α 上，F 的运动占比、复杂引擎的使用和画面主体的非文字程度，都低于 N 或 M。
- **H4**（第一阶段）：F 的概念比 N 的更集中：聚类更少，场、色彩和字体更趋同。
- **H5**（第一阶段）：N 在干净上下文里的众数，不是装备黑名单里的那些旧 slop（cream 底、渐变字、玻璃拟态、漂浮粒子等）。
- **H6**（第一阶段，稳定性假设）：N 的 4 张概念卡之间差异有限，大多数落在 2 簇以内，所以单抽能够代表这一组。

### 3.2 预测（冻结前记录，之后不改）

- **用户**（2026-09-25 的立场，冻结前可以补充或修改）：装备很多内容的价值很值得商榷，当前模型在干净上下文里能自己做出新颖的反 slop 设计。对应的预期是 H1 成立。
- **审查者**（Claude Opus 5.5，方向加把握程度）：
  - P1：F **不会**在两个 brief 上都排第一。把握较大。
  - P2：H3 在 brief α 上成立。把握中等。
  - P3：H4 成立。把握中等。
  - P4：H5 成立。把握较大。
  - P5：M 和 N 谁高，不做预测。
  - P6：F 的 R1 客观缺陷数不低于 N（即知识轴不减少客观缺陷，审查 §4.7）。把握偏低。

**α「冬夜泳池」（画面驱动；预计对 N 更有利）**
- **brief**：城市公共游泳馆「北湖游泳馆」（虚构）开放冬季夜场，每晚 19:00–22:30。受众是本市下班后的年轻人。要传达：「外面零下五度，水里二十八度。」调性：安静、温暖、带一点奢侈的放松。
- **spec**：1920×1080 横屏，12 秒（360 帧），30fps，无声。屏上文案由设计师决定，但必须出现场馆名和夜场时间。
- **为什么选它**：文字少，天然适合大面积动态画面（水、蒸汽、雪），同时有很强的品类反射（蓝色水波焦散），适合观察当前模型的众数和能力上限。

**β「断网同步」（信息驱动；预计对 F 更有利）**
- **brief**：开源、本地优先的笔记应用「Tern」（虚构）发布 2.0。新功能：同一局域网内的多台设备自动同步，不经过任何服务器。受众是在意隐私的开发者和写作者。要传达：「你的笔记从不离开你的房间。」调性：冷静、可信、不炫技。
- **spec**：1080×1920 竖屏，15 秒（450 帧），30fps，无声。必需文案：应用名 Tern、版本号 2.0、一句核心信息（措辞由设计师决定）。

**统一为无声**：用户已确认简单的合成音效可以接受（审查 §2），但实验里去掉声音，可以让评判只比较画面。

**第一阶段的评判者**：每个 brief 起 1 个新的通用 agent。它只拿到打乱顺序、换成随机 ID 的全部卡片，不知道分组。指令逐字如下：

```
下面是同一条 brief 的若干份独立的动态影片概念卡。brief:⟨BRIEF⟩
1. 按"设计方向"聚类:底层想法或隐喻相同的归为一簇,即使配色、字体不同。给出每簇的卡片 ID 和一句簇描述。

3. 列出你在多张卡之间看到的重复元素(场、色彩、字体、隐喻、开场、收尾)。
只依据卡片文字判断,不读取任何其他文件。
```

**第一阶段的指标**：
- **M1.1**：每组 4 张卡占几簇（1–4）。
- **M1.2**：F 卡（以及 M 卡、P 卡）有多大比例落在含 N 卡的簇里，也就是“离开了裸众数”还是“重复裸众数”。
- **M1.3**：属性集中度，由脚本从卡片字段统计：暗场占比、色相族（按色值分桶）、字体重复率、“画面主体”的分布。
- **M1.4**：各组切题度和可预期度的均值。
- **M1.5**：N 卡里有没有出现装备黑名单上的元素（对应 H5）。
- **H6 的判定**：N 卡只占 1–2 簇，视为稳定；占 3–4 簇，视为不稳定。如果不稳定，第二阶段的结论一律标注为“单抽代表性不足”，只能作为方向性证据。

### 5.4 第二阶段：成片（每组单抽）

- 每个 brief 起 3 个 builder（N、M、F 各 1 个，随机对应 `draw-1..3`），并行，各自跑到 `draw 定稿`（包括自己的检查和重渲）。这一阶段不跑盲选，也不进甲乙环。

  - 施工失败（多次尝试后仍渲不出来）：用同一组重抽 1 次；“施工失败”本身记为一项结果。
  - 越界读取（事后审计发现读了其他 draw、仓库文档、以往作品）：作废并重抽。
  - 上下文丢失：如果已经报过定稿，就用已报的 canonical 版本；否则重抽。
- **事后隔离审计**：解析每个 builder 转录里的 Read 路径。允许读的只有：自己的 RUN_DIR、`plugin/tools/`、本组被指定的装备（F 组是 `plugin/skills/design-brain/reference/`，M 组是 `kit/design-equipment.md`）、RBP 目录，以及 WORKSPACE 下的 `node_modules`（查 API 用）。结果记进 RUN-LOG。这次**真的做审计**（对应审查 §5 第 4 条）。

### 5.5 第二阶段的评判

**J1 用户盲评（主终点）**
- 每个 brief 的 3 支片以 `review/draw-1.mp4` 等中性标签给用户，同时附上各自的 `still-*.png`。**不提供 DESIGN.md。**
- 用户填写 `_studio-0925/<brief>/USER-RANKING.md`（模板见附录 A），**锁定之后才能打开映射表**：
  - Q1 **潜力排序**（主终点）：如果之后能继续精修，哪一支上限最高。这与生产盲选的判准一致。
  - Q2 当前完成度排序。
  - Q3 每支一句理由。
  - Q4 猜哪一支是“完整装备”组、哪一支是“无装备”组，各给出把握程度（1–3）。
- 允许并列，但要明确写出。

**J2 盲选 agent（次终点）**
- 逐字使用 `BLIND-SELECT-PROTOCOL.md`，N=3，候选就是这 3 支。
- 先取 winner；再起一个新实例，只给剩下 2 支，取 winner，得到完整排序。
- 候选的字母顺序做 2 种不同的排列，各跑一遍，所以每个 brief 共 4 次盲选运行，每次都是新实例。
- 记录两种排列下排序是否一致。

**J3 客观缺陷审计（次终点，可选）**：新起一个通用 agent，不知道分组，只拿到各 draw 的 R1 和 canonical 版本的 held 帧、`strip-manifest.json` 和 `index.tsx` 里的字符串字面量。逐项计数：
1. 核心文案可读性受损（对比塌陷、被线条穿过）。必须做原分辨率裁切。
2. 文字贴边（距画面边缘小于 4%）或被裁切。
3. held 帧里文字互相重叠。
4. 文字落在全帧最亮区。
5. 每段文字停留的字数 ÷ 秒数：中文超过 7 字/秒，英文超过 3 词/秒，记为超速。秒数取 manifest 里对应 PAUSE 段的帧数。
6. 屏上文案里出现 em dash。

**描述性指标**（脚本计算，不做判定）：
- **引擎手段**：在代码里 grep `three|@react-three|WebGL|getContext\(|<canvas|ShaderMaterial|glsl`。
- **运动占比**：`strip-manifest.json` 里 MOTION 段帧数 ÷ 总帧数。
- **画面主体**：由 J3 的审计者按“文字 / 物体 / 大面积动态画面 / 混合”归类。
- **屏上文字密度**：总字数 ÷ 时长。
- **定稿前的渲染次数**：`out/r*` 目录数。
- **成本**：builder 的工具调用数、从首次调用到定稿的墙钟时间、转录里有 usage 字段时的 token 数。

### 5.6 第三阶段：进环（可选，看预算）

- 每个 draw 各起 1 个新的甲，逐字使用 `CRITIC-PROTOCOL.md`，跑到 `CONVERGED: YES`。实验里设上限 4 轮，到上限就标注“封顶”。
- **摆渡消息**：M 组和 F 组用生产版的每轮摆渡消息（`CRITIC-PROTOCOL.md` 里“每轮摆渡消息”那一节）。N 组没有环纪律，改用中性版：

  ```
  批评意见 Round ⟨REVIEW_ROUND⟩ — 受评条带 ⟨STRIP_DIR⟩(逐字):⟨判词⟩
  自己判断每条要不要改;改完两条渲染命令输出到 ⟨NEXT_OUT_DIR⟩,在新真帧上确认落地,追加 FIXES.md,回报 round ⟨REVIEW_ROUND⟩ done。
  ```
- **指标**：
  - 第 1 轮高 / 中严重度的条数。
  - 收敛轮数。
  - 甲有没有提出“太复杂 / 太写实 / 要简化”这一类意见，逐条记录。这用来检验审查 §4.11 的补充点：甲的评判准则里带着能力时代的假设。
  - §A 有没有漂移。
- **收敛后**：用户对收敛版本再做一次 J1 盲评（只做 Q1），用来佐证第二阶段的结论。

## 6. 判定规则（主终点 J1-Q1）

**单个 brief 的结果**：
- **F 胜**：F 严格排第一。
- **F 负**：有另一组严格排在 F 前面。
- **平**：其他情况，包括和 F 并列第一。

**总判定**：

| 判定 | 条件 | 对生产的含义 |
|---|---|---|
| **D1 保留** | 两个 brief 都是“F 胜” | 完整装备在当前模型上仍然净正。保留它，下一步做组件拆解实验，再看审查的 R2、R6、R7 |
| **D2 退役** | 两个 brief 都是“F 负” | 完整装备不再作为生产默认。新基线取 N、M 中两个 brief 排名之和更好的那一组；并列时取 M（§4 有独立的产出证据，审查 §4.3）。审查 R7（重排 texture）作废，R4（测量工具）按 J3 的数据决定 |
| **D3 未决** | 其他情况 | 追加第三条 brief（同样每组单抽），按 3 条里的多数重新套用 D1 / D2。仍然分裂，就不改生产，并在结果里写明 |

**附加规则**：
- 如果 H6 判为不稳定（§5.3），D1 或 D2 都降级为“方向性证据”，改生产之前先补第三条 brief。
- J2（盲选）在两个 brief 上都和 J1 相反时，记为“盲选准则与用户判断不一致”，作为审查 R8（重审甲和盲选的准则）的证据。**J2 不能推翻 J1。**
- 用户在 Q4 里两个 brief 都高把握且猜对了 F，说明“装备外观”可能已经能被认出来，存在破盲风险。结果照样采用，但要在结论里注明。
- 第三阶段的结论如果在两个 brief 上都推翻第二阶段，两组结果都要报告；在分歧解决之前（追加一条 brief）不改生产。

## 7. 对有效性的威胁

1. **每组单抽**：单抽方差无法直接测量，只能用第一阶段的 H6 间接估计。本实验只能看出肉眼明显的大差距。这一点是按用户的成本约束、在“当前模型能力较为稳定”的假设下接受的。
2. **破盲**：用户看过大量装备时期的作品，可能认得出“暗场 + 单一红或琥珀 + Fraunces + 颗粒”这种装备外观（审查 §4.4）。Q4 用来量化这个风险。
3. **评判者的准则偏向**：盲选协议的质感条款（光污染、“判设计不判摄影”）诞生于装备时期，可能偏向 F、惩罚 N 的复杂画面。所以主终点定为用户，J2 只作参考。
4. **自检不对等**：N 组没有 §4 人格，只有一句“修到满意”，执行层可能吃亏。主终点定为“潜力”，就是为了降低执行差异的权重；执行差异单独由 J3 报告。
5. **brief 效应**：两条 brief 分别偏向 N 和 F（§4.1），本身就是一种有意的平衡。两条样本代表不了所有 brief。
6. **组件归因**：M 对 F 同时去掉了知识轴和锚点（§2.2），本实验不做逐个组件的归因。
7. **模型与环境**：结论只对受测模型、冻结版本和当天的 Remotion / RBP 版本成立。
8. **编排者知道映射**：编排者不做任何评判，但它发给评判者和用户的消息里不能带出任何分组线索。

## 8. 成本（相对量）

- **第二阶段（必做）**：6 个 builder 从头跑到定稿，约等于两次生产运行的抽卡阶段；另加 8 次盲选运行和 1 个审计 agent。
- **第一阶段**：必做部分每个 brief 8 个纯文本实例，两个 brief 共 16 个；加上可选部分共 32 个；另加 2 个评判者。每个实例的成本远低于一次成片 draw。F 卡每个实例要读约 90KB 装备，M 卡约 13KB。
- **第三阶段（可选）**：6 个甲，每个最多 4 轮，加上对应的 builder 修复轮。
