# 读 Impeccable 4.4.0：对装备重设计的启发（2026-09-26）

> **状态：阅读笔记，未验证。** 读的是本机插件缓存里的 4.4.0，与上游 `pbakaus/impeccable` 的最新提交 `9d715cc`（2026-09-24）一致。项目当初的 `aesthetic.md` 摘的是更早版本的 General rules / Copy / Absolute bans / AI-slop test 几节（现归档在 `docs/archive/design-axes/`）。4.4 里这些内容已拆进 `craft-floor.md` 和 `new-work.md`，整体结构也变了。

## 1. 它现在的样子

- **文字层仍以静态清单和硬规则为主**：
  - 字体黑名单（Fraunces、Newsreader、IBM Plex、Space Grotesk 等），附语"你停止寻找了"；
  - "你测得的呈现先验"：温暖、书卷气的题材会出奶油底、衬线、灯光；
  - 大量"违反即合同违约，不论什么 harness、什么模型"的措辞。

  这正是我们的消融刚刚退役的那一类：快速过期、负向设防。
- **机制层走得更远**：它把模型不擅长的事从 prompt 里挪进了流程和工具。
  - 用骰子分配方案；
  - 用测量关卡代替自我感觉；
  - 用新上下文的评审；
  - 限定轮数；
  - 建之前先写短合同，建完再写文档。

  这部分和模型代际关系小，值得借鉴。

## 2. 值得借的

### 2.1 多样性不靠"求新"（对应用户指出的坑）

`new-work.md` §3 和 `concept-seed`：
- 模型先从受众自己的世界（他们熟悉的器物、场所、仪式、出版物、图形传统）列出 7 个**有根据**的候选，按共鸣度排序。列表本身要跨至少三个材料家族。
- 然后由骰子决定建哪一个。理由原话："你排第一的方向，就是每次运行都会交付的那个。"
- 目录里的"挑战者"只按两个正向维度比较：受众认同、产品清晰度。
  - 原话一："输给扎实的有根据方案，是正当的结果。"
  - 原话二："熟悉而有效是正当的终点，不是胆怯。"
- 模型自己的第一名总会作为一张卡展示给用户，品类的标准做法也始终作为一个出口保留。

结构上，**多样性放在搜索和分配里，选择只按正向标准**。我们的预注册草稿把两者混在一起，把多样性当成了过关条件。

**对我们的可能用法**：不必叫任何一抽"与众不同"。可以让一次概念阶段产出排好序的有根据候选，把不同候选分给不同的 draw，并固定一抽建第一名，再由盲选按潜力挑。这是一个待测的机制，前提是诊断证明"模型的第一名不总是最好的"。

### 2.2 可以用来编码用户理由的正向标准（候选标签，不是规则）

- **记忆测试**：看完一小时后，观众会怎么描述它？如果答案是一种氛围，说明概念还没定下来。
- **具体性**："换一个不相干的产品，这个构图和视觉语言能原封不动地用吗？"这是替换测试的正向版本。
- **演示，不陈述**：让主体做它自己的事，展示竞争对手抄不走的细节。γ 上 J2 批评 N、F "叙事靠文字卡陈述"，称赞 M "把换手变成可看见的书写动作"，正是这一条。
- **峰终**：情绪路径上有没有峰值，结尾有没有落点。
- **模式决定"好"的含义**：说服（观众要被说服并行动）、阅读（观众要看懂）、体验（作品本身领衔）。同一套评判不适用于三种片子。

### 2.3 输入侧：委托问的是目的，不只是规格

`new-work.md` §2、`shape.md`：
- 谁必须行动，他们应该相信什么；
- 这里有什么独一无二的真实，是邻近产品或通用模板说不出来的；
- 什么样的结果即使打磨得很好也会让人觉得不对。

明暗不设默认，由"谁、在哪、什么光线下使用"这一句物理场景来决定。

我们的委托步只问规格（画幅、时长、文案、音频）。brief 薄，模型能用的就只有品类，出来的就是品类答案。α 的 N 被评为"创意平平无奇"，可能有一部分出在这里（未验证）。

### 2.4 流程

- **建之前写短合同，建完再写文档。** 方向合同只有 6 块、约 150 字：THESIS、OWN-WORLD、STORY、FIRST VIEWPORT、FORM、FINISH，附语"哪一块读起来像一种氛围，方向就还没定"。完整的 DESIGN.md 在建完之后，由另一个 agent 从成品里写出来，原因是"建之前写的规则书会被拿来对抗现实，而不是描述现实"。对照我们：M 的 DESIGN.md 在 γ 上 161 行，N 47 行，F 219 行，而完成度（Q2）三条都是 N 最好。长设计文档是否在消耗完成度，值得作为一个假设。
- **自检限定轮数。** 建完检查一轮、批量修、最多再确认一轮就停："无止境的自我质检花着用户的钱，把交接环节能做得更好的事做得更差。"我们的 builder 在定稿前渲了 3–5 版（结果文档 §4.5）。
- **评审先看，后读合同。** 完成评审被要求先用自己的话清点对照稿里的元素，再读方向合同和 builder 写的任何摘要。父进程对"修了什么"的叙述不算证据。
- **测量在视觉判断之后进来。** critique 规定设计评审必须先完成，检测器的结果才能进入综合，因为"检测器输出是确定性的，但它仍然会锚定判断"。这一条已补进第二只眼睛的设计原则。

### 2.5 能力侧：栅格素材

建之前先用图像模型出对照稿，建的时候把插画、照片、质感做成真正的栅格素材，不用 CSS 模仿材质。原话："模仿出来的材质，是机器设计最可靠的标记。"对照我们：α M 右下角的 CSS 光球，α F "读作茶或酒而不是泳池"的平直渐变液体。这可能是一个天花板层面的杠杆，但需要接入图像模型，还有 API 成本和素材来源的问题，需要用户决定，暂不纳入。

## 3. 不借的

- **字体黑名单、"呈现先验"之类的静态清单**：负向设防，随模型代际过期。按 Dogma 的教训，只说别去哪，不说去哪。
- **"不论什么模型"的强制口吻，以及重型状态机**：这是为了约束会漂移的模型设计的。我们的消融在当前模型上看到的是文字越少越好。
- **网页 UI 专属的规则**：各种交互状态、浏览器表面、导航、表单等，在短片里没有对应物（审查 §4 已指出同类问题）。

## 4. 一个交叉印证，不是结论

Impeccable 实测的 AI 界面聚类之一是"温暖的奶油底、高反差衬线标题、赤陶或信号红强调"。这几乎就是我们 β 的 N 和 M（米色纸面、衬线、朱红尺寸线），以及 γ 的 N 和 M（米色墙面或米黄纸面、衬线、朱红）。β 三组都用了 Newsreader 配 IBM Plex Mono，两者都在它的黑名单上。

所以当前模型自发的"反 slop"设计，本身很可能就是当下的默认味道，审查 §4.12 预言过这一点。

用户对 β 的评价"2/3 的平面设计风格可能初看更专业、抓眼球"不能用来反驳这一点。那是三组之间的相对比较，本身还带着"可能""初看"的保留；比 F 好，不等于惊艳。**更正**：本节初版把这句话当成了反证，属于过度解读，用户指出后改正。

这个聚类出现在两条毫不相干的 brief 上（笔记应用、修表铺），说明它是模型不看题目的默认，不是某条 brief 的答案，因此是黑名单的合格候选（见 §5）。

## 5. 对下一步的影响

- **诊断**：
  - 让 N0 产出一份排好序的有根据候选，而不只是一张卡。用户给所有候选打分。
  - 由此可以直接测"模型的第一名是不是它最好的"，不需要假设少见就是好：如果第一名稳定最好，就不需要分配机制；如果不是，§2.1 的分配机制就有了依据。
  - 用户理由的编码以用户原话为准，§2.2 只作候选标签。
- **黑名单的位置**（用户 2026-09-26 补充的反向逻辑）：黑名单可以用来剔除"常见而且一定不惊艳"的味道。这和"跳出常见 ≠ 好"并不矛盾：落在常见的默认味道里，足以判定不惊艳；离开常见，却不足以判定为好。所以黑名单只做剔除，不当目标，剩下的方案再按正向标准挑。Dogma 死在禁令是唯一的目标函数；禁令作为正向装备之下的地板，是另一回事。
  - **候选怎么来**：跨不相干 brief 反复出现的味道（配色、字体、母题的组合）。例如 β、γ 的"米纸 + 衬线 + 朱红"，F 在三条 brief 上都出现的"暗场 + 暖色强调"。反过来，同一条 brief 内几抽一致的 conceit 可能就是这条 brief 的正解（γ 的换指针，用户评为"更有视觉冲击力"），不进黑名单。单位是组合，不是单个元素：直接禁掉衬线或 Newsreader，会误伤。
  - **怎么确认**：诊断改用绝对尺度，以"惊艳"为顶端锚点，另加一问"这个方向有没有可能做到惊艳"。落在某个味道里的卡片如果始终到不了顶端，就列入黑名单。清单在当前模型上实测，换代时重测。
  - **放在哪，待测**：
    - 放进乙的装备，会有提示效应，也会过期（审查 §1.3 的 18/18；装备自己也记着"§B 亲手打过'避'勾，照样渲了出来"）；
    - 放在乙之外做过滤：在概念阶段或盲选那一层判断"是否落在已知味道"，命中就退回，保留 conceit、换味道，这样乙的上下文就不用背这张清单。
- **装备逐条审查的候选项**：
  - 委托问目的，并用观看场景决定明暗（§2.3）；
  - 短合同代替长 §A/§B（§2.4）；
  - 自检限定轮数（§2.4）；
  - 评审和测量的先后顺序（§2.4）；
  - 栅格素材（§2.5，需用户决定）。
